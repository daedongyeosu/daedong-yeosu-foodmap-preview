# 가게 목록 개수 계산의 중복 정렬 제거

2026-10-20 · preview 전용

## 확인된 사실과 한계

- 기존 배포 후 검사39316091387은 Fast4G·CPU4배·390×844에서 누적 long task4063ms/기준4000ms로 실패했다. 나머지 조건은 통과했다. 63ms짜리 단일 오류가 아니라21개의 긴 작업 누적이다.
- 원래 실행은 함수별 trace를 남기지 않았다. 따라서 당시4063ms 전부가 한 함수에서 발생했다고 소급 확정하지 않는다. 코드 그대로의 독립 실행이 통과하는 환경 차이도 보존한다.
- 같은 preview 소스의 CPU 추적에서 `storeListPagerMetrics → filteredStores → 위치·영업상태 정렬` 경로의 반복 비용을 확인했다. 가로 위치/페이지 범위를 계산할 때 필요한 것은 개수뿐인데, 전체 정렬을 매번 다시 실행했다.
- 고정 입력 회귀검사에서10번의 측정이10번의 전체 정렬을 실행하여 수정 전 실제 실패했다. 이 중복은 실행 환경과 무관하게 재현된다.

## 변경

- `app.js`가 원래 화면을 만들면서 이미 구한 목록 개수를 `WeakMap`에 기억한다. 상품이나 가게를 새로 정렬·숨기거나 목록 자체를 캐시하지 않는다.
- pager는 같은 원본/같은 필터 조건의 개수만 재사용한다. 카탈로그 배열 교체·길이 변경, 필터 함수 교체, 검색·카테고리·브랜드·주소·좌표·거리 조건 변화는 무효화한다.
- 초기32개 뒤에 전체 목록이 도착해도 활성 목록 DOM은 바꾸지 않고 개수만 한 번 재계산한다. 다음 같은 상태의 스크롤은 전체 정렬을 다시 실행하지 않는다.
- 코어 helper가 아직 없는 구형/혼합 로딩에서는 기존 계산 경로를 유지한다. 빈 목록0과 카테고리 목록의 실제 표시 개수도 보존한다.
- 저장소/사진/가격/꾸밈/주문·지도 링크/영업상태 정렬 기준은 변경하지 않는다. 새 보정 스크립트나 예약 작업을 추가하지 않는다.

## 검사

- `pager-rendered-total-regression-test.mjs`: 정상 재사용,32→36 배경 갱신, 같은 크기 교체, append, 필터/주소/좌표 변경, 카테고리·빈 목록·구형 fallback.
- 기존 가로 목록 브라우저 검사: 자유 스크롤, 정확한36개 범위, 늦은 영업시간/위치 갱신,2px 이내 화면 앵커·광고·팝업·복귀 보존.
- 기존 성능 검사 파일·프로파일·모든 budget/timeout은 수정하지 않는다. 추적 도구를 뺀 최종 로컬 실행은 CPU4/Fast4G에서 홈5156ms, 최대104ms, 누적368ms로 기존 기준을 통과했다. 로컬 수치를 GitHub 배포 후 수치로 표현하지 않는다.
- 최초 개수-only 초안에서32개가 남는 문제가 브라우저 검사로 검출돼 배포하지 않았고, 원본 snapshot/필터 조건 무효화로 수정 후 같은 검사를 통과했다.
- 별도 구형 사진 fixture는 앱 아이콘을 상품사진으로 사용해 수정 전/후 모두 실패했다. 원래 검사 파일/판정은 변경하지 않았다. 실제 기존 사진을 사용한 동일 assertion의 격리 추가 검사는 사진 src/완료/원본 크기 조건을 통과했다.
- 실제 배포 후 공식 검사 성공은 별도로 확인하며, 실패하면 기준을 낮추거나 성공할 때까지 반복 실행하지 않는다. 물리 휴대전화 검수와 실결제·배송·배차 시험은 수행하지 않는다.
