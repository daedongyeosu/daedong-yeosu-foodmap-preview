## 운영 방법 (별도 유료 서비스나 반복 AI 작업 불필요)
- 본문 원본: `data/native-pages.json`.
- 게시 결과: `/info/umi/`, `/info/healing-yacht/`, `/info/small-business/`.
- 본문 변경 후 `node scripts/build-native-pages.mjs`로 로컬 자산만 사용하여 다시 생성한다.
- 새 사진을 사용하면 `node scripts/build-native-pages.mjs "가게별_통합 폴더의 실제 경로"`로 필요한 파일만 반영한다.
- 페이지 생성 과정은 네트워크 호출·Notion API·Bitly API·AI 호출을 하지 않는다.
- 변경 결과는 기존 검증/PR/승인 절차로 게시한다. 이 방식은 셀프서비스 관리자 편집 화면을 대체한다고 주장하지 않는다.

## 아직 필요한 작업
1. 기존 관리자에 인증된 가게/홍보 편집·사진 업로드·임시저장·공개 기능 추가. 현재 확인한 관리자는 통계/수정요청/우천운영만 제공한다.
2. 서버의 기존 주문 경로 중 Bitly 주소가 남았는지 전체 목록/상세 대조. 광고 3개 변경만으로 모든 주문 링크 독립을 단정하지 않는다.
3. 이미 인쇄된 bit.ly QR 목록과 최종 도착지 매핑 확인. 기존 QR은 변경 불가능하므로 Bitly 연결은 유지하거나 전단지를 교체해야 한다. 본 변경은 Bitly 계정/도착지를 수정하지 않는다.
4. 신규 등록 시 로컬 원본을 받는 경로를 정식 관리자 저장소와 연결. Notion만을 필수 입력으로 요구하지 않는다.
5. Preview 검수/승인 뒤 최신 운영 브랜치에 필요한 변경만 반영. Preview 전체를 운영에 덮어쓰지 않는다.

## 호환성
`notionUrl`, `data-rc6-banner-notion`, 세션 복귀 키는 기존 복귀 로직의 호환 필드명이다. 실제 새 도착지는 동일 출처 `/info/.../`다. 단순히 변수에 notion이라는 이름이 남았다고 런타임 의존성은 아니다. 기존 인쇄 QR와 과거 유입 통계 필드는 삭제하지 않는다.
