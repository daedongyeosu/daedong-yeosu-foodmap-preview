# 맛지도 상점 꾸미기 비교 분석과 적용 기준

확인일: 2026-10-16. 공식 사용 설명서와 제품 소개를 읽고 비교했다. 타사 유료 편집기를 실제 조작하거나 소스코드를 분석한 것으로 표현하지 않는다. 성능·매출 효과를 검증한 자료가 아니다.

## 구현 경계

- 현재 편집기는 사진 최대 40개를 사용하는 평면 진열 시안이다. 구역은 하나의 진열장을 나누는 것이며 실제 방·통로·3D 이동을 구현한 것은 아니다.
- 내부 좌표와 화면 비율을 4:3으로 유지해 기기 폭에 따라 물건과 선반의 상대 위치가 달라지는 문제를 줄인다. 회전된 사진의 모서리까지 고려해 공간 밖으로 벗어나지 않게 한다.
- 투명 사진은 투명 여백만 잘라 물건의 아래쪽이 선반에 맞도록 처리한다. 원본 파일은 바꾸지 않는다. 완전히 투명한 이미지는 오류로 안내한다. 불투명 배경을 자동으로 지우는 AI 배경 제거와는 다르다.
- 위치 잠금은 이동·크기·회전·삭제를 막는다. 이름·숨김·그림자·겹침 순서는 계속 수정할 수 있다. 복제물은 잠금과 숨김을 해제한 상태로 만든다.
- 숨김은 이 배치 시안에서 고객 미리보기까지 숨기는 기능이다. 판매 상품을 품절시키거나 실제 판매를 중지하는 기능과 다르다.
- 저장은 현재 브라우저의 IndexedDB에 사진과 배치 하나를 저장한다. 계정별 저장·다중 매장·기기 간 동기화·백업은 미구현이다.
- 자동 배경 제거·AI 착장·AI 인테리어·실제 결제·배송은 이 편집기와 아직 연결되지 않았다. 사장님이 직접 등록한 주문 링크와 아래의 등록 상품 연결을 지원한다.

## 매장 방문과 배달 주문 연결 (2026-10-16 추가)

- 사장님이 실제 주소·영업시간·전화번호·지도 공유 링크·가게 주문 링크·배달/포장 안내를 작성한다. 이 정보도 기존 기기 내 시안과 함께 저장한다.
- 고객 미리보기 상단에 방문·주문·전화 동작을 보여준다. 등록하지 않았거나 형식이 잘못된 링크는 연결 준비 중으로 표시하고 활성 링크를 만들지 않는다. 지도 링크는 사장님이 제공한 네이버/카카오지도 HTTPS 링크를 사용하며 주소로 장소 ID를 추측하지 않는다. 해당 장소와 실제 가게의 일치 여부를 자동 검증한 것은 아니다.
- 진열한 사진에 상품 설명과 개별 주문 링크를 붙인다. 개별 링크가 비어 있으면 '가게 주문 화면 열기'로 안내하고, 개별 링크가 있으면 해당 주소를 그대로 사용한다. 가격·옵션·재고·배송비·도착 예상은 연결된 주문 화면에서 확인하도록 안내한다.
- 실제 매장 사진은 '사장님이 꾸민 온라인 공간'과 구분해 표시한다. 고객 공개나 계정별 서버 저장은 아직 없다.
- 테스트는 임시 브라우저 컨텍스트와 가상의 테스트 주문 페이지로 수행한다. 실제 상점 전화·실제 주문·결제를 실행하지 않는다.
- 방문 링크 클릭을 실제 방문, 주문 링크 클릭을 주문 완료로 간주하지 않는다. 실적 측정은 향후 실제 주문원장과 구분해 설계한다.

## 다음 검증 순서

1. 실제 사장님이 안내 없이 사진 선택 → 진열 → 수정 → 되돌리기 → 재방문을 수행하게 하고 막힌 지점을 기록한다.
2. 실제 커피·빵·철물·의류 원본사진에서 배경 제거의 정확도와 수정 작업량을 시험한다. 톱니·손잡이 구멍·투명 유리는 별도 확인한다.
3. 아래 상품 연결을 실제 등록 상점과 대조하고, 옵션이 필요한 상품과 상점 정보·배송견적 연결을 추가 검증한다. 복수 진열을 별도 재고로 만들지 않는다.
4. 작은 매장에서 먼저 검증한 뒤 공간 계층과 자산 불러오기 방식을 확장한다. 수백 진열대·수만 상품을 현재 40사진 구조에 그대로 넣지 않는다.
5. 실제 기기·사진 수별 초기 표시시간, 드래그 반응, 메모리, 저장 실패율을 측정한다. 성능 수치 없이 대형 매장 지원을 약속하지 않는다.

## 등록 상품과 기존 장바구니 연결 (2026-10-16 추가)

- 상점번호를 입력해 기존 `/api/store-orders/preview/catalog`의 상품을 읽기 전용으로 불러온다. 확인된 ID를 사진에 연결하며, 시안에는 가격·재고 사본을 저장하지 않는다. 연결은 기기 내 시안으로 저장하고 재방문·고객 미리보기 때 상품정보를 다시 조회한다.
- 상품 연결이 있는 사진은 수동 외부 링크보다 등록 상품 연결을 우선한다. 품절·확인 필요·가격 미등록·조회 실패·삭제 상품은 주문 링크를 활성화하지 않는다. 상점을 바꾸면 확인 후 기존 연결을 해제한다. 이 확인은 편집 실수를 방지할 뿐 상점 소유권 인증이 아니다. 계정별 상점번호 자동 선택은 후속 작업이다.
- 고객이 사진을 누르면 서버에서 읽은 이름·가격·재고를 표시하고 기존 온라인 상점의 해당 상품 확인 화면으로 이동한다. 이동만으로 장바구니에 넣거나 주문하지 않는다. 현재는 진열장 안의 즉시 담기가 아니라 기존 장바구니로 이어지는 단계다.
- `catalogStore` 경로는 예시상품으로 대체하지 않으며 상점별 장바구니 저장키를 분리한다. 같은 ID의 사진 여러 장은 같은 상품으로 연결한다. 수량 조절·0개 삭제·재방문 복원·재고 상한을 기존 장바구니에서 사용한다. 서버 상품 갱신 때 삭제·품절·재고 감소를 반영하고 조정 사실을 안내한다.
- 상품 조회·장바구니 저장은 재고 예약이 아니다. 기존 주문 확인 단계의 서버 견적에서 가격·재고를 재확인해야 한다. 복수 기기 구매의 최종 재고 경쟁은 주문 서버가 처리해야 하며, 이번 브라우저 검사가 이를 검증한 것은 아니다.
- 390×844 Chromium 검사에서 가상 상품·상점과 대체한 API 응답으로 같은 상품의 복수 진열, 상점별 장바구니, 수량·삭제·복원, 품절·조회 실패·빈 목록·잘못된 상점번호를 확인한다. 실제 상품원장 수정·주문 생성·전화·결제·배송은 실행하지 않는다.
- 실제 운영 상점의 상품과 대조, 옵션 선택, 계정별 공개·저장, 상점 주소·지원금 등 주문 정보, 실제 배송견적·상점 접수·토스 결제·배송까지의 검증은 아직 남아 있다.

## 상품등록부터 배송요청까지 로컬 통합검사 (2026-10-16 추가)

- 신규 입점 시 공용 `demo-yeosu-store` 대신 기기 내 초안에 보관하는 독립적인 preview ID를 발급한다. 기존 공용 demo 초안도 다음 저장 때 새 ID로 복사하며 과거 서버 주문은 삭제·이전하지 않는다. 이 ID는 상점 인증·사업자 심사나 정식 가입을 대신하지 않는다.
- 입점 화면의 저장된 고객 상점 링크와 꾸미기 상품 조회가 같은 상점번호를 사용한다. 사진·배치만 바꿔도 상품원장을 바꾸지 않는다.
- 등록 상품 경로는 같은 상점번호의 기기 내 입점 초안에서 픽업 주소·상세주소·지원금·최소주문액 등을 가져온다. 다른 상점 초안은 사용하지 않는다. 현재 서버 상품 API에는 이 매장 설정이 없으므로, 다른 기기에서 가게 주소를 확인하지 못하면 빈 출발지로 배송견적을 요청하지 않고 안내한다. 정식 공개 전 서버의 인증된 매장 설정 연결이 필수다.
- 고객이 가격 확인 주문서를 보고 있는 동안 자동 상품 조회가 확정된 가격 토큰을 지우지 않도록 한다. 등록 상품 주문은 가격 확인 토큰 없이 전송하지 않는다. 주문 성공 후 재고를 다시 조회한다.
- `scripts/browser-store-commerce-flow.mjs`는 `STORE_PREVIEW_SOURCE`로 지정한 기존 backend checkout의 TypeScript 주문 처리기를 직접 불러오고 SQLite `:memory:` DB에 두 테스트 migration을 적용한다. 주문·가격·재고·상태변경 응답을 가짜 문자열로 만들어 통과시키지 않는다. 검증한 처리기 SHA-256: `d8151151211ea4057448920ac5ed04ab06ad0eccadadb3c1cf586edfc7cd5ba6`.
- 390×844 브라우저에서 입점 양식의 상품등록과 저장 → 고객 장바구니 → 주소 선택 → 서버 서명 가격확인 → 테스트 주문 1건 생성 → 상점 수락/준비/포장확인 → 배송요청 → 고객 상태조회까지 검증했다. DB 재고 3→2와 고객 상품화면 갱신, 포장 미확인 차단, 픽업 주소 누락 시 견적 차단도 확인한다.
- 모든 API 요청을 로컬 처리기로 대체한다. 주소검색과 도로거리 견적은 시험 응답이다. 이 검사는 실제 배포된 서버·라우팅·토스·기사 배차·픽업·배송완료를 검증하지 않으며, 주문 처리기의 현재 마지막 상태는 `DELIVERY_REQUESTED`다. backend 소스와 운영 DB는 변경하지 않는다.
- 남은 출시 조건: 계정/상점 소유권 인증, 기기와 무관한 매장 설정·사진 저장, 옵션/품절/취소·환불, 서버 주문 중복방지·연결 불확실 주문 처리, 결제 검증 후 배송요청, 배송 연결모듈의 배차/픽업/완료 상태 회수와 실제 기기 실증. 이번 로컬 검사만으로 실서비스 준비 완료라고 표현하지 않는다.
