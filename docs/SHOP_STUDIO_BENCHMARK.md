# 맛지도 상점 꾸미기 비교 분석과 적용 기준

## 2026-10-17 재계획: 기능 수보다 사장님의 작업 완주

사용자 요청에 따라 신규 장식 기능 추가를 멈추고 아래 순서로 진행한다. 아래는 **공식 자료에서 확인한 제품 동작**, **맛지도 직접 사용 관찰**, **우리의 설계 판단**을 구분한 계획이다. 타사의 내부 실패 이력·유료 편집기 실사용·매출 개선을 확인했다고 주장하지 않는다. 이후 옛 항목은 당시의 구현 기록이며 최신 기능/저장 한도는 현재 소스와 PR 설명을 기준으로 한다.

공통 기능의 존재만 확인한 자료다. 그 기능이 생긴 내부 시행착오, 실제 상점의 완료율, 유료 기능별 지원 범위는 미확인이다. 제품 전체를 복제하지 않고 작업 흐름 원칙을 적용한다.

### 2. 수정 전 직접 사용 관찰

- AI가 사장 역할을 맡은 점검이며 실제 사장님 참여 시험이 아니다. Codex 브라우저에서 390×844와 데스크톱을 사용한다. 사용자 시안을 보호하려고 별도 로컬 origin `127.0.0.1:4193`에서 테스트했다. 실제 서버·상품 원장·결제는 쓰지 않았다.
- 초보 빵집 경로: 빈 화면 → 간판 이름 실제 키보드 입력 → 파일 선택 창으로 기존 연출용 빵 사진 3장 선택 → 가구 도구 열기 → 유리 쇼케이스 추가. 사진·가구와 로컬 저장은 동작했다.
- 처음 화면에서 사진 선택 버튼 top 약 1,326px, 진열장 top 약 2,504px였다(DOM 측정). 휴대폰 첫 화면에는 결과 공간이 보이지 않고 설정부터 읽어야 했다. 도구를 펼치면 결과와 선택한 가구 편집 위치가 더 멀어진다.
- 세밀하게 꾸미는 경로의 첫 문제: 도구를 찾고 가구를 추가한 뒤, 결과 공간과 선택한 대상 편집기로 돌아갈 간단한 경로가 없다. 도구 개수가 아니라 화면 왕복 비용을 먼저 줄여야 한다.
- 첫 자동 fill 시 이름 변경이 반영되지 않았으나 실제 키보드 입력 후 간판·저장은 정상 확인했다. 이를 제품 이름 저장 버그로 단정하지 않는다.

### 3. 우선순위와 완료 조건

1. **P0, 이번 수정:** 휴대폰은 진열 공간을 먼저 보여주고, 사진/가구/선택한 대상 편집/공간 보기로 바로 이동한다. 기존 상세 도구는 없애지 않는다. 새 상품·장식 기능은 추가하지 않는다.
   - 390×844 새 화면에서 진열장 시작 위치 650px 이내를 목표로 측정한다.
   - 가구·사진을 선택한 뒤 '선택한 것 수정'으로 현재 대상만 찾아간다. 대상이 없으면 버튼을 비활성화하고 이유를 안내한다.
   - 경로 이동 자체는 기존 시안·사진·상품 연결·undo 이력을 변경하지 않는다. 고객 미리보기와 공개 화면에는 편집 경로를 숨긴다.
2. **P1:** 최소 작업 경로와 자유 꾸미기 경로를 구분한다. 사진 3장으로 기본 상점을 끝낼 수 있어야 하며, 세밀한 사용자는 모든 기존 도구에 접근해야 한다. 여러 배치 방법을 새로 늘리기 전에 용어·도구 노출·진행 상태를 검토한다.
3. **P1:** 저장·공개 구분을 실제 배포 환경에서 검증한다. 현재 계정 저장 준비본과 최신 편집 UI가 일치하도록 배포 전 재준비한다. 미배포 상태를 사용자 가입·공개 완료라고 보고하지 않는다.
4. **P2:** 상점 소유권 확인이 된 실제 상품으로 연결·옵션·품절·방문/주문 이동을 검증한다. 공개·결제·기사 실증은 별도 승인과 환경이 필요하다.
5. **P2:** 실제 사장님 참여 시험. 초보자/세밀한 꾸미기 사용자에게 사진 올리기→배치→수정→실수 복구→미리보기→다시 열기를 맡기고, 도움 요청 지점·실수·미완료 단계·소요시간을 기록한다. AI 역할 점검으로 이를 대신했다고 주장하지 않는다.
6. **P3:** 위 경로가 안정된 뒤 상품 수별 성능·접근성·기기 호환을 측정하고, 필요한 도구만 추가한다. 수백 진열장/수만 상품/3D/가상 착장은 별도 설계와 검증 전 약속하지 않는다.

출시/채택 기준은 '자동 검사 수'가 아니라 작업을 끝낼 수 있는지와 복구·저장 신뢰성이다. 자동 검사는 이미 되는 기능을 지키는 보조 근거로 쓴다.

### 4. 실행 기록

- **P1 사진 여러 장 연속 수정 동선(2026-10-17):** 사용자 시안과 분리된 `127.0.0.1:4195`, 390×844에서 파일 선택 창으로 연출용 빵 사진3장을 올리고 목록의 식빵 사진을 선택했다. 수정 전에는 진열장으로 강제 이동해 이름 입력칸 top 약896px, 포커스는 문서 본문으로 빠졌다. 목록 선택은 이름·설명을 고치는 경로로 바꾸고 수정 패널에 ‘사진 목록으로’/‘진열장에서 보기’를 제공했다. 기존 진열장 선택·끌기와 가구 도구는 바꾸지 않았다.
- 수정 후 같은 경로에서 이름 top212px, 설명 top270px 및 이름 입력 포커스를 확인했다. 실제 키보드로 식빵 이름·설명을 입력→목록의 해당 사진으로 복귀→다른 사진 이름 수정→진열장 확인→되돌리기로 직전 이름 복구를 직접 수행했다. 돌아갈 때 검색/필터는 유지하며 이름 변경으로 검색 결과가0개가 되면 검색칸으로 돌아간다. 이동만으로 시안·상품 연결·되돌리기 이력을 만들지 않는다.
- `scripts/browser-shop-studio-photo-workflow.mjs`를 병합된 이전 JS로 실행하면 목록 선택 후 포커스 검사에서 실패하고, 수정 JS에서는 통과한다. 목록/수정/공간 왕복, 필터에서 빠진 이름 복구, 숨김·위치 잠금 상태의 편집과 이동 방지, undo/redo, 재접속, 데스크톱·모바일 가로 넘침 없음, API 쓰기0건을 검증했다. 이 시험은 AI 역할 점검과 브라우저 화면 크기 재현이며 실제 사장님 참여·휴대폰 가상키보드·TalkBack/VoiceOver 검증을 대신하지 않는다. undo 이후 선택 해제와 저장/공개 용어 이해도는 후속 점검 대상으로 남긴다.

- **P1 기본 사진 편집 우선 배치(2026-10-17):** 별도 로컬 origin `127.0.0.1:4194`, 390×844에서 AI가 초보 사장 역할로 파일 선택 창→크루아상 사진 추가→선택한 것 수정 경로를 직접 사용했다. 수정 전 이름 입력 top은 536px, 설명 입력 top은 888px여서 설명은 첫 화면 밖이고 상품등록 안내가 앞에 있었다. 이름·설명·구역을 먼저 배치하고 판매 연결에는 별도 제목을 붙였다. 기존 사진 교체·진열대 연결·상품 연결·상세 도구는 삭제하지 않았다.
- 같은 조건에서 이름 top 154px, 설명 top 212px로 바뀌었다. 실제 키보드로 이름·설명을 입력하고 새로고침→다시 선택해 보존을 확인했다. 사진 등록 자체가 공개 판매를 뜻하지 않는다는 안내와 가격·재고 확인 절차는 유지했다. 자동 브라우저 시험도 기본 입력칸 가시성·순서·재접속 보존, 사진 교체·상품등록 전달, SKU 연결·장바구니 보호를 검증한다. 사용자4192 시안과 실제 상품·주문 데이터는 변경하지 않았다. 이는 역할 점검이며 실제 사장님 완주율 검증은 여전히 남아 있다.

- 조사·위 관찰·우선순위를 먼저 기록한 뒤 P0 화면 동선 개선을 진행한다. 수정 후 같은 사진·가구로 공간→편집→되돌리기→미리보기→재접속을 다시 점검하고 아래에 결과를 추가한다.
- 아직 실제 사장님 참여 시험, 타사 편집기 계정 실사용, hosted 저장/공개 왕복을 완료하지 않았다.
- **P0 수정·역할 재점검 완료:** 휴대폰에서 공간을 도구 목록보다 먼저 배치하고, 사진/가구/선택 항목/분위기/저장 안내/방문·주문으로 이동하는 경로와 공간 복귀를 제공했다. 모든 기존 세부 도구는 유지했다. 경로 이동은 시안·상품 연결·undo 이력을 변경하지 않는다.
- 동일한 390×844 조건에서 첫 진열장 top이 약 2,504px에서 **614px**로 줄었다. 사진 3장과 쇼케이스 1개, 변경한 간판이 재접속 후 보존됐다. 선택한 사진 편집으로 이동했을 때 패널 top 약 100px와 해당 패널 포커스를 확인했다.
- Codex 브라우저 직접 조작으로 사진 선택 창→3장 추가, 실제 키보드 간판 입력, 쇼케이스 추가, 선택 사진 수정 경로, 그림자 변경→되돌리기, 공간 복귀, 고객 미리보기→꾸미기 복귀를 확인했다. 미설정 전화/지도/주문 버튼은 비활성으로 표시됐다. 실제 상품/주문/결제·서버 공개를 실행하지 않았다.
- `scripts/browser-shop-studio-owner-flow.mjs`가 같은 목표를 독립 브라우저에서 재검증한다. 경로 이동 후 undo 한 번이 '마지막 가구 추가'를 취소하는지 확인해 탐색만으로 저장/이력이 생기지 않게 보호한다. 집중 보기에서 도구로 복귀하는 상태와 1280px 데스크톱 2열도 확인한다.
- 남은 문제를 기능 추가로 덮지 않는다: 현재 상세 설정 문구와 도구 수는 여전히 많다. 시작 경로 간소화, 숨김/판매 중지의 이해도, 상품 연결 완료 여부 안내, 실제 저장/공개 환경, VoiceOver/TalkBack 및 시각적 순서와 키보드 탐색 순서의 적합성을 다음 시험 대상으로 둔다. 이번 수정으로 초보자 완주율이 검증됐다고 표현하지 않는다.

- 간판 글자/바탕색·3종 글씨·차양, 바닥색, 구역명, 상품 이름표, 기본 공통 선반 표시/숨김을 편집한다. 상품의 구역 이름으로 고객 상품목록을 분류한다.
- 가구 종류는 나무 진열장·유리 쇼케이스·벽 선반·계산/픽업대·안내판·창문·화분이다. 각각 문구·색·가로/세로 크기·위치를 조절하고 마우스/터치 이동, 잠금·숨김·복제·앞뒤 순서·삭제·되돌리기를 지원한다. 가구 30개, 상품사진 40개 제한을 유지한다.
- 상품사진을 가구 ID에 연결하면 가구 이동 때 같이 이동하며 화면 경계 안에서 그룹 이동량을 제한한다. 연결 상품의 위치가 잠겼으면 그룹 이동도 막는다. 가구 크기 조절은 사진을 자동 확대하지 않으며 가구 복제는 상품을 복제하지 않는다. 가구 삭제는 상품을 보존하고 연결만 해제한다. 복잡한 자동 선반 채우기·3D 충돌·실제 방 이동을 구현했다고 표현하지 않는다.
- 개별 사진 자동 정리는 가구에 연결된 상품을 고정 장애물로 취급하여 보존한다. 연결 상품은 공통 선반 자동 맞춤도 적용하지 않는다. 쇼케이스 배치를 자동 정리가 덮어쓰지 않도록 구분한다.
- 작은 화면은 공간 전체 보기/가까이 보기(가로 이동)와 큰 상품사진 목록을 함께 제공한다. 동일 상품의 복수 진열은 고객 목록과 체험 장바구니에서 SKU 하나로 취급한다. 체험 장바구니는 수량·개별 삭제·전체 비우기·예시 합계를 지원하며 새로고침 때 초기화된다. 판매용 장바구니·실제 재고와 분리한다.
- 내 상점은 기존 IndexedDB `scene`, 시범매장은 `scene-bakery-example-v1`로 분리 저장한다. 기존 내 시안을 시범매장으로 덮어쓰지 않는다. 시안 보관 파일은 JSON 형식·버전·사진 종류·외부 URL 차단·사진/가구 수·파일 크기를 검사한다. 내 상점과 시범매장 파일은 각 화면에서만 복원한다. 복원 전 확인과 복원 후 되돌리기를 제공한다.
- `scripts/browser-shop-studio-bakery.mjs`는 390×844와 1440×1050에서 이미지 표시, 상품 분류·체험 담기/수량/삭제, 확대, 실제 마우스/터치 가구 이동·연결 사진 이동·잠금, 문구·글씨 변경, undo/redo, 파일 내려받기/복원·오류 파일 거부, 재접속, 원래 시안 보존, 외부 요청 없음 등을 확인한다. 실제 휴대전화 하드웨어·메신저 브라우저 검증과 시각/운동 장애 사용성 평가는 별도로 남아 있다.
- 생성 이미지 원본은 보존했다. 프로젝트용 5개 이미지는 alpha가 있는 WebP(최대 640px)로 합계 367,332 bytes다. 생성 도구와 정확한 프롬프트는 `assets/studio-bakery/README.md`에 기록한다. 최초 WebP 파일 크기만 확인한 것으로 수천 상품·3D 매장의 성능을 검증한 것은 아니다.

## 서로 다른 견본과 골목 탐색 (2026-10-17)

- 베이커리 외에 모퉁이 옷장·엄마손 반찬가게·든든 철물상회를 같은 편집기로 만들었다. 의류는 행거·수동 마네킹·전신거울, 반찬은 타일 벽·쇼케이스·픽업대, 철물은 공구판·부품함을 사용한다. 새 가구 5종은 기존 색/크기/이동/그룹/저장 도구를 그대로 사용한다. 마네킹은 평면 장식 위에 사진을 사람이 배치하는 것이며 자동 착장·3D 모델링은 아니다.
- `examples.js`가 견본 ID와 상품·기본 디자인을 관리한다. 기존 베이커리의 저장키는 보존하고 다른 견본마다 독립적인 키를 사용한다. 내 시안과 분리하며, 견본 장바구니는 각 화면의 임시 상태다. 다른 견본의 백업은 거부하고 잘못된 견본 ID는 골목으로 돌려보낸다.
- `store-alley/index.html`에서 네 가게를 구경하고, 각 가게에서 해당 가게 위치의 골목으로 돌아올 수 있다. 2D 견본이며 실제 지리정보나 실영업점 목록이 아니다. 홈의 기존 무료입점 문구/버튼은 그대로 두고 별도의 견본 골목 링크를 추가했다. 공개 배포는 preview 병합 승인 뒤 별도로 확인한다.
- '이 분위기로 시작하기'는 해당 견본의 기본 디자인을 내 편집기에서 검토하는 경로다. URL을 여는 것만으로 저장된 시안을 바꾸지 않는다. 명시적 버튼과 확인 후 가구·색·구역 등 디자인만 적용하고, 기존 상품사진·상품 ID·가게정보·catalogStoreId는 유지한다. 사진의 기존 가구 연결은 해제하며 undo로 이전 디자인을 복원한다. 견본 상품·가격·체험 SKU·주소·연락처를 판매상품으로 복사하지 않는다.
- 온라인 공간 입점비/권리금/월세 없음과 실제 판매·결제·배송·플랫폼 비용은 구분해 안내한다. 수익이나 매출을 보장하지 않는다. 실제 정식 입점·상품등록·결제·기사 수행은 기존 별도 구현/검증 경계를 유지한다.
- `scripts/browser-shop-alley.mjs`는 네 가게 탐색, 상품보기·체험 담기, 견본 간 저장/장바구니/백업 분리, 잘못된 견본, 템플릿 확인 취소/적용/되돌리기, 기존 상품·전화·상점번호 보존, 화면 넘침을 확인한다. 테스트용 브라우저와 가짜 연락처를 쓰며 실제 API 쓰기를 하지 않는다. 원래 베이커리·편집기·상품 연결·주문 로컬검사도 함께 재검증한다.
- 상품 이미지 6장은 내장 image_gen으로 생성하고 원본을 보존했다. alpha가 있는 최대 640px WebP 합계 299,180 bytes를 프로젝트에 저장했다. 정확한 프롬프트는 `assets/studio-alley/README.md`를 참조한다.
