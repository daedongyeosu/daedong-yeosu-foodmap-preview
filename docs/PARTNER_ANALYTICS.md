# 공유 배달대행 유입 구분

## 고객 링크와 측정 의미

| 주소 | entrySource | 의미 |
| --- | --- | --- |
| /s?m | partner_sms | 공유업체 문자용 표식 |
| /s?q | partner_qr | 공유업체 QR용 표식 |
| /s | partner_link | 공유업체, 문자/QR 미구분 |
| /?m | map_sms | 일반 지도 문자용 표식 |
| /?q | map_qr | 일반 지도 QR용 표식 |
| /?hero=가게ID | store_link | 가게전용, 매체 미구분 |

가게전용은 표식 뒤에 기존 hero/store ID를 그대로 붙인다. 기존 /s 우선노출,
가게 QR, 합쳐진 가게 ID, 주문경로는 바꾸지 않는다. 이전 partner 쿼리는
폐기된 상태 그대로이며 새 유입 식별자로 사용하지 않는다.

한 문서의 첫 진입 때 유입경로를 확정한다. 가게를 바꿔 열거나 주문버튼을
누를 때는 유입경로는 그대로, 대상 storeId는 실제 누른 가게로 기록한다.
새 직접 방문에 공유업체 유입을 붙이지 않도록 출처를 브라우저 저장소에
영구 보관하지 않는다. m/q가 동시에 있으면 매체 미구분이다.

QR 표식 주소 방문은 실제 카메라 스캔 횟수가 아니다. 같은 주소를 문자로
보내면 매체를 정확히 구분할 수 없다. 옛 store_qr/store_qr_legacy 분류는
호환용으로 유지하며 관리자에서는 옛 가게전용·매체 미구분으로 표시한다.
기존 direct에는 과거 /s 유입이 섞였을 수 있고, 이를 소급 추정하지 않는다.
주문경로 클릭은 주문완료/매출이 아니다. 익명 기기는 사람 수가 아니다.

## 관리자와 배포

기존 운영 관리자 /api/events 및 /api/analytics를 그대로 사용한다.
추가 개인정보, 새로운 관리자 계정, 새로운 데이터베이스 열은 없다.
관리자 코드가 새 entrySource를 먼저 허용한 뒤 고객 코드를 배포해야 한다.
역순 배포 시 새 출처가 unknown으로 저장될 수 있다.

사용자에게 Preview 및 운영 배포 승인을 받은 후에만 병합한다.
관리자 수정본과 모바일 검증 자료는 별도 기존 Sites 프로젝트에 보관한다.
기존 QR 이미지 파일은 이번 작업에서 변경하지 않았다.

## 확인한 검사

- 신규 partner-analytics-regression-test.mjs: SMS/QR/미구분/충돌/가게진입/신규방문 격리
- 공개 저장소 감사·정적·데이터·문법 검사 통과
- 활성 회귀검사 147개 통과, 기존 비공개 자료 전환에 따른 4개 제외는 유지
- 390×844 실제 브라우저 로컬 부팅: /s 문자, /s QR, 미구분, 가게 QR, 직접방문
- 기존 관리자: 빌드/33개 검사, SQLite 집계·중복전송·권한·필터 검사
- 관리자 데스크톱/390×844: 문자 및 QR 주소 생성, 가게 ID 보존, 가로 넘침 없음
- 검증 데이터는 로컬 fixture만 사용; 운영 통계에 테스트 기록을 보내지 않음
