# 이웃장터: 처음 쓰는 사람의 휴지통 동선

2026-10-20 · 초기 요청은 PR까지만이었으며, 후속 사용자 지시로 **검사 통과 후 preview만 병합·배포**를 승인받았다. 운영 메인·실결제·배차는 변경하지 않으며 예약 작업을 만들지 않는다.

## 문제와 변경

- 기존 휴지통은 아래쪽 도구에 있고, 끌기를 시작한 뒤에만 버리는 영역이 나타났다. 처음 쓰는 사람이 방법을 찾아야 했다.
- 같은 `trashSelected` 버튼 하나를 선택한 사진·소품 근처에 표시한다. 누르기만 해도 기존 복구 가능한 휴지통 모델로 이동한다. 잠금·저장 중에는 사용할 수 없다.
- 다른 사진·소품·가격표·크기 손잡이를 가리지 않는 빈 곳에 표시한다. 공간이 없으면 같은 버튼을 진열판 바로 아래에 배치한다. 버튼을 복제하지 않는다.
- 휴지통 보기·개수와 복구 진입을 진열판 바로 아래에 고정한다. 끌 때는 그 자리가 큰 ‘여기에 놓으면 휴지통으로’ 영역이 되고, 안에 들어오면 색과 문구가 바뀐다. 도구를 아래로 스크롤해도 버릴 곳이 멀어지지 않는다.
- 뺀 직후 가까이에 ‘방금 빼기 되돌리기’를 제공한다. 새 물건 선택이나 다른 편집을 하면 이 전용 바로가기를 숨긴다. 이전 휴지통 작업을 핑계로 이후의 다른 편집을 취소하지 않는다. 일반 되돌리기·다시 하기와 휴지통 복구는 그대로다.
- 휴대폰에서는 공통 저장·휴지통·조절 손잡이 공간을 제외한 실제 진열판/도구를40:60으로 시작한다. 경계 드래그·방향키·Home/End·기본 버튼으로 높이를 조절한다. 화면 배치만 바꾸며 사진·꾸밈·저장본을 변경하지 않는다. 도구 최소 높이를 보장하므로 좁은 화면의 최대 비율은 실제 한도로 표시한다. PC·가로 화면의 기존 두 열은 유지한다.

## 보존과 검증

- 저장 형식·DB 이름·저장 키는 바꾸지 않는다. 이동 전 원래 사진·원본사진·가격·면·좌표·크기·잠금·소품을 기존 `trashItem`/`restoreItem`으로 보관한다. 자동 저장·공개·자동 삭제를 추가하지 않는다. 후속 사용자 요청에 따라 확인을 거친 휴지통 삭제·비우기만 추가한다.
- 새 회귀검사는 장터 안의 단일 버튼, 도구 밖 휴지통 위치, 누적 취소 보호, 위치 경계와 밀집 화면 fallback을 검사한다. 원래 코드에서 진열판 옆 휴지통 부재로 실제 실패했다.
- 기존 브라우저 휴지통 검사에 터치 선택→옆 버튼→정확한 보관→즉시 되돌리기와 키보드 경로를 추가한다. 원래의 드롭·취소·실패·잠금·크기 조절·다른 면 복구·기기 저장·새로고침·용량/오래된 창 보호 assertion은 유지한다.
- 테스트의 화면 크기 전환 뒤에는 두 프레임의 레이아웃을 기다리고 터치 좌표를 측정한다. 성능 budget/timeout을 늘리지 않는다. 좁은 화면의 버튼 가림과 작은 진열판 문제는 검사에서 검출 후 수정했으며 실패 자료는 로컬에 보존한다.
- 기존 홈 내비게이션 회귀검사의 공통 휴지통 문구 assertion만 실제로 바뀐 짧은 버튼 문구에 맞춘다. 홈 링크/두 열/한 줄 혜택/뒤로가기/저장 실패 보호 assertion은 변경하지 않는다.
- 모든 브라우저 시험은 별도 기기 저장공간과 실제 Chromium 터치를 사용한다. 실제 물리 휴대전화 검수가 아니며 외부 쓰기를 차단한다. 사용자 사진·기존 초안·메인·관리자·젠딜리·결제·배차·기존 수집기는 변경하지 않는다. 예약 작업을 만들지 않는다.

## 후속 요청: 이전·다음,40:60,확인 삭제

- 진열면 탐색에 ‘이전 면 / 다음 면’ 글자를 표시한다. 첫 면과 마지막 면의 실제 경계를 검사하며 단순 화면 이동으로 초안을 변경하지 않는다.
- `workspace-layout.js`는 화면 전용 모듈이다. 비율은 열린 화면에서만 유지하고 장터 원장/사진/기기 DB에는 쓰지 않는다. 취소된 드래그는 원래 비율로 돌아가며, 방향키와25~75% 범위/동적 도구 최소 높이·40% 초기화를 지원한다. 공통 버튼을 비율 계산에서 제외하고 아주 작은 진열판은 가격표와 크기 손잡이를 화면에 맞게 축소/배치한다.
- 기존 사진/끌기 검사는 새 높이 조절의 End 키를 실제로 사용해 사진 편집 공간을 확보한 뒤 동일한 기존 assertion을 실행한다. 별도 새 검사는 조절 전 실제40:60·터치 드래그/취소/키보드/초기화·초안 불변을 검사한다. 화면 회전은 두 프레임 정착 후 측정한다. budget/timeout/워크플로를 변경하지 않는다.
- `deleteTrash`는 확인된 ID 목록에 대해서만 불변 복사본에서 휴지통 항목을 제거한다. 진열 중인 사진·소품·면은 유지하며 없는 ID/중복/빈 대상은 거절한다. 비운 뒤 기존 version1/2로 돌아가며 사진 저장 형식은 그대로다.
- UI는 대상 이름/개수를 먼저 보여주고 ‘취소’에 초점을 둔다. Escape·취소는 그대로 유지하며, 목록/초안 snapshot이 바뀌면 삭제를 거절한다. 삭제 후에도 현재 편집기의 되돌리기는 가능하다. 삭제 상태를 명시적으로 저장하고 다시 연 뒤에는 휴지통에서 복구할 수 없다고 안내한다. 원본 파일·내보낸 시안·다른 기기의 사진까지 지우는 기능이 아니다.
- 휴지통 안의 ‘장터 변경 저장’은 기존 저장 함수를 재사용한다. 현재 꾸밈까지 함께 저장한다고 안내하고, 실패/용량/오래된 창은 이전 저장본과 현재 입력을 유지한다. 삭제 확인만으로 저장하지 않는다.
- 기존 휴지통 브라우저 검사에 새 전용 검사를 연결해 PR CI에서도 함께 실행한다. 새 모델 회귀검사와 독립 모바일/PC 시험이 개별 삭제·전체 비우기·취소·되돌리기·저장/재열기·quota/stale 보존을 대조한다. PR488에만 추가하며, 후속 승인에 따라 모든 필수 검사 성공 후 preview에만 반영한다.

## preview 반영 전 낮은 화면 검사 보완

- PR 검사39329758602에서 기존 첫 사용자 검사가390×460 진열판 높이70px로 실패했다. 실제 공통 버튼과 간격이 화면을 차지했고, 레이아웃 정착 전 임시 높이의 상한값이 사용자의40% 설정을 영구 축소하는 문제도 확인했다.
- 낮은 세로 화면에서는 공통 휴지통 줄의 패딩과 줄 사이 빈 간격만 줄인다. 터치 버튼44px·도구 최소136px·기본40:60을 보존하면서390×460 진열판84px/도구 약142px을 확보한다. 사진·꾸밈 좌표나 저장본은 바꾸지 않는다.
- 선호 비율과 화면에 표시 가능한 실제 비율을 분리했다. 임시 크기 제한은 선호값을 덮어쓰지 않으며 드래그는 현재 보이는 비율에서 시작하고 취소는 원래 선호값으로 돌아간다.
- 같은 브라우저 검사에390×460 초기 진입과 실제84px/도구134px 이상 검증을 추가했다. 변경 전 실패를 보존하고 기존 높이·성능 기준은 낮추지 않는다. 기존 첫 사용자 검사도 그대로 실행한다.
