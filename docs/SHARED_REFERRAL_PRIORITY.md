# 공유 배달대행 우선노출 링크

## 작업 계약

- 문제: 공유 배달대행이 보내는 지도 링크에서도 기존 관리 가게가 우선 표시된다.
- 변경: `?partner=shared-yeosu`로 진입한 문서에서만 검수한 공유 가게를 우선한다.
- 보존: 일반 루트 주소, 가게전용 hero 화면, 가게 데이터·주문 링크·사진·공통 광고·검색 조건·영업상태 순서.
- 완료 조건: 모바일에서 공유 링크와 일반 링크의 순서가 분리되고 가게 상세를 정상 이용할 수 있다.

## 범위와 데이터

`data/store-priority.json`의 `referralProfiles`에는 공개 지도 ID만 보관한다. 원본 주문 내역, 고객·기사 정보, 사업자번호, 전화번호, 배달대행사 구분은 게시하지 않는다.

초기 후보는 52개 가게다. 주문 엑셀에서 기존 관리 목록과 전화·이름·지역을 대조하여 제외한 후, 동일 명칭과 지점/동네가 확인되고 고객 목록에서 실제 표시되는 지도 ID만 포함했다. 별칭만 맞는 다른 브랜드, 중복 후보와 과거 노출 제한 가게는 보류했다. 사업자번호가 없는 자료이므로 사업자번호 검증 결과라고 주장하지 않는다. 추가 후보는 동일성 확인 후 반영한다.

## 동작

- 영업상태를 먼저 정렬하고 같은 상태 내에서는 공유 가게 우선, 이후 기존 지역·거리 순서를 따른다.
- 홈 가게 슬라이드는 해당 프로필 가게 중 기존 노출 조건을 충족한 가게를 사용한다. 공통 광고 3개는 유지한다.
- 검색·카테고리·주문앱 조건에 맞는 후보 안에서만 순서를 바꾼다. 가게를 삭제하거나 검색에서 숨기지 않는다.
- 기존 관리 가게의 고정 카테고리/추천 슬롯은 이 링크에서만 적용하지 않는다.
- 프로필은 최초 문서 URL에서 읽고 저장소에 기록하지 않는다. 같은 문서의 상세 닫기/뒤로가기에서는 유지하고, 새 일반 루트 진입에서는 해제된다. 미등록 프로필 및 고흥에서는 적용하지 않는다.
- 기존 가게전용 `hero`가 함께 있으면 가게전용 슬라이드가 우선한다.

## 배포

Preview PR 검증과 모바일 브라우저 검수 후 사용자 병합 승인을 받는다. 메인 병합·배포에는 별도 승인이 필요하다. 승인 전 링크를 배포 완료로 안내하지 않는다.
