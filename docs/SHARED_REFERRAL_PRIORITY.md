# 공유 배달대행 우선노출 링크

## 작업 계약

- 문제: 공유 배달대행이 보내는 지도 링크에서도 기존 관리 가게가 우선 표시된다.
- 변경: `/s`로 진입한 문서에서만 검수한 공유 가게를 우선한다. 이전 `?partner=shared-yeosu` 주소는 사용자 요청으로 폐기하며 일반 지도 진입으로 정리한다.
- 보존: 일반 루트 주소, 가게전용 hero 화면, 가게 데이터·주문 링크·사진·공통 광고·검색 조건·영업상태 순서.
- 완료 조건: 모바일에서 공유 링크와 일반 링크의 순서가 분리되고 가게 상세를 정상 이용할 수 있다.

## 범위와 데이터

`data/store-priority.json`의 `referralProfiles`에는 공개 지도 ID만 보관한다. 원본 주문 내역, 고객·기사 정보, 사업자번호, 전화번호, 배달대행사 구분은 게시하지 않는다.

우선노출 대상은 102개 가게다. 최초 52개에 사용자 승인에 따른 근사 후보 50개를 추가했다. 보류 57개 이름·주소 항목 중 53개를 상호·별칭·주소 또는 인접 지점 후보에 연결했다(중복 제거). 관련 지도 후보가 없거나 가장 가까운 후보가 기존 관리 가게여서 제외된 3개 항목과 의료기관 1개는 포함하지 않았다. 기존 관리 가게 ID는 제외했다.

사용자는 이 작업이 QR 발급/사업자 동일성 확정이 아닌 우선노출이라는 점에서 근사 후보도 포함하도록 명시적으로 요청했다. 따라서 근사 후보를 검증된 동일 사업자나 실제 제휴 관계라고 표시하지 않는다. 기존 가게의 이름·주소·주문 링크는 수정하지 않는다. 원본과 후보 대응표는 PC의 비공개 검수 자료로만 보관한다.

백년족발·노랑통닭 여서문수점·가마치통닭 여서점도 공유 링크의 지정 가게로 포함한다. 일반 루트에서는 기존 후순위 설정을 그대로 적용한다.

## 동작

- 영업상태를 먼저 정렬하고 같은 상태 내에서는 공유 가게 우선, 이후 기존 지역·거리 순서를 따른다.
- 홈 가게 슬라이드는 해당 프로필 가게 중 기존 노출 조건을 충족한 가게를 사용한다. 공통 광고 3개는 유지한다.
- 검색·카테고리·주문앱 조건에 맞는 후보 안에서만 순서를 바꾼다. 가게를 삭제하거나 검색에서 숨기지 않는다.
- 기존 관리 가게의 고정 카테고리/추천 슬롯은 이 링크에서만 적용하지 않는다.
- 프로필은 최초 문서의 `/s` 경로에서 읽고 저장소에 기록하지 않는다. 같은 문서의 상세 닫기/뒤로가기에서는 유지하고, 새 일반 루트 진입에서는 해제된다. 고흥에서는 적용하지 않는다.
- GitHub Pages의 `/s/` 진입 파일은 루트 문서로 이동한 후 `shared-entry.js`가 앱 실행 전에 주소를 `/s`로 복원한다. 원본 루트 HTML을 중복 복사하지 않으며 기존 주문앱 복귀 쿼리·해시는 보존한다. 임시 해시 표식은 즉시 제거한다. 공유 버튼도 `/s`를 제공한다.
- 기존 가게전용 `hero`가 함께 있으면 가게전용 슬라이드가 우선한다.

## 배포

Preview PR 검증과 모바일 브라우저 검수 후 사용자 병합 승인을 받는다. 메인 병합·배포에는 별도 승인이 필요하다. 승인 전 링크를 배포 완료로 안내하지 않는다.
