# 고객용 메뉴 묶음: 표시용 투영과 보존 원칙

## 목적과 적용 범위

`menu-family-model.js`는 가게별 메뉴를 고객이 살펴보기 쉬운 묶음(family)과 원본별 변형(variant)으로 만드는 **표시 전용 모델**이다. 모델 버전은 `menu-families-1-20260905`다.

고객 화면에서 여러 항목이 한 묶음으로 보이는 것은 원본 항목을 삭제하거나 주문앱의 메뉴를 변경했다는 뜻이 아니다. API 입력, 가게 정체성, 주문 링크, 사업자 정보는 이 모델의 수정 대상이 아니다. 다른 가게의 메뉴를 서로 묶지 않는다.

이번 적용 범위는 Preview 시험이다. 운영 반영은 별도 명시적 승인과 검증을 거쳐야 한다.

## 묶음과 차이 보존

- 같은 가게 안에서 보수적으로 정규화한 메뉴명으로 묶음을 만든다. 공백·표기 차이와 명확히 구분된 홍보 배지를 처리하되, 이름 중간에 포함된 단어까지 임의로 지우지 않는다.
- 불명확한 별칭, 비슷하게 들리는 이름, 재료·조리법이 다른 음식을 추측으로 자동 통합하지 않는다.
- 용량·중량·개수 차이는 구조화된 수량 정보와 원문 변형에 각각 남긴다. 서로 다른 수치를 같은 값으로 교정하지 않으며, 용량이 없는 항목에 수량을 추정해 넣지 않는다.
- 일반·제로 음료, 서로 다른 음료 종류, 인원수, 순살·뼈, 맵기, 세트·단품 등의 의미 차이를 보존한다. 수량이 같다는 이유로 종류가 다른 메뉴를 합치지 않는다.
- 하나의 묶음 안에서도 고객이 실제 차이를 확인할 수 있어야 한다. 화면 요약 시 이름·사진·설명뿐 아니라 구조화된 수량·옵션 차이도 고려한다.
- 음식이 아닌 안내와 회원 전용 항목은 별도 제외 기록으로 추적한다. 음식명에 안내와 비슷한 글자가 포함됐다는 이유만으로 숨기지 않는다. 리뷰 선택·추가 요청은 필요한 경우 별도 옵션으로 유지한다.

## 메뉴 표시와 사진 크기

- 음식·사이드·음료·주류·추가 옵션은 모두 일반 메뉴 목록에 표시한다. 음료·주류라는 이유로 기본 접거나 별도의 펼침 버튼 뒤에 숨기지 않는다. 분류에 따른 정렬은 항목 숨김과 구분한다.
- 음료·주류도 음식과 같은 전체 크기의 메뉴 카드와 사진 영역을 사용한다. 작은 보조 썸네일로 축소하는 별도 표시 규칙을 적용하지 않는다.
- 묶음의 용량·구성 상세는 펼쳐 확인할 수 있다. 펼친 원본별 사진도 카드 폭에 맞는 큰 사진 영역에 표시하며, 사진 비율을 보존한다. 원본별 이름·설명을 함께 보여 주고 서로 다른 변형의 사진과 설명을 섞지 않는다.
- 전체 크기는 화면 폭에 맞춘 표시 크기를 뜻한다. 원본 사진 참조를 교체하거나 새 사진을 생성한다는 뜻이 아니며, 사진이 없는 항목에 임의 사진을 넣지 않는다. 기존 사진 표시 안전 규칙은 유지한다.
- 점진적 렌더링·지연 이미지 로딩은 성능을 위해 유지할 수 있지만, 스크롤하면 모든 메뉴를 확인할 수 있어야 한다. 고객이 직접 선택한 검색·분류 필터를 제외하고 메뉴 종류 때문에 항목을 감추지 않는다.

이 표시 원칙은 초기 Preview의 음료·주류 기본 접힘과 축소 카드 규칙을 대체한다. 원본 데이터, 묶음 기준과 보존 집계는 변경하지 않는다.

## 원본과 참조 보존

- 입력 객체를 직접 수정하지 않는다. 같은 입력의 결과는 결정적이어야 하며, 이미 투영한 결과에 다시 적용해도 결과가 달라지지 않아야 한다.
- 원본 항목의 식별자와 이전 참조는 `__sourceIds`로, 원본 행의 위치는 `__inputIndex`로 추적한다. 식별자가 반복되더라도 원본 행을 임의로 없애지 않는다.
- 각 원본은 `__variants`의 변형 또는 사유가 있는 제외 기록 중 정확히 한 곳에 대응해야 한다.
- 원본별 이름·수량·사진 참조·설명은 변형에 보존한다. 대표 카드의 사진과 설명은 같은 대표 변형을 기준으로 선택해 서로 다른 원본의 정보를 한 메뉴처럼 섞지 않는다.
- 고객용 가격 제거와 기존 사진 표시 안전 규칙은 유지한다. 화면에서 가격이나 부적합한 사진이 보이지 않는 것과 원본 보존 여부는 구분해 감사한다. 원본 응답은 공개 저장소 밖에 별도로 보존한다.
- 현재 검증한 공개 API 항목에는 `id`, `name`, `description`, `category`, `image`만 있었다. 모델의 `__quantity`는 이름에서 추출한 표시용 정보다. 현재 자료에 구조화된 옵션이 없다는 사실을 향후 입력에도 옵션이 없다는 가정으로 사용하지 않는다.

## 공개 금지와 운영 경계

공개 저장소·문서·커밋에 원본 메뉴 JSON, 가게별 메뉴 목록, 실제 원본 식별자, 사진 주소, 가격값, 비공개 데이터 위치를 넣지 않는다. 수집 응답과 감사 보고서는 공개 저장소 밖에 둔다.

고객 화면에는 가격, 회원 전용 표현, 원시 감사 기록과 내부 검증 집계를 노출하지 않는다. 이 문서의 집계는 기술 검증 기준이며 고객용 전체 가게 수 표시를 허용하는 근거가 아니다.

모델과 감사 도구는 원본 삭제·API 데이터 변경·주문 실행·배포를 수행하지 않는다. Preview 승인은 운영 변경 승인으로 확대 해석하지 않는다.

## 감사 실행

읽기 전용 공개 API 수집으로 만든 스냅샷을 준비하고, 아래 자리표시자를 로컬의 비공개 디렉터리로 바꿔 실행한다. 실제 경로를 문서나 커밋에 기록하지 않는다.

```bash
node scripts/audit-menu-families.mjs --input "<PRIVATE_SNAPSHOT_DIR>" --output "<PRIVATE_REPORT_DIR>"
node menu-family-audit-regression-test.mjs
```

다른 모델 파일을 검증하려면 `--model` 인자를 사용할 수 있다. 입력과 보고서 디렉터리가 공개 저장소 안에 있으면 감사 도구가 거부한다. 감사 실행 자체는 네트워크 요청이나 원본 파일 수정을 하지 않는다.

감사는 다음을 확인한다.

- catalog에 있는 모든 가게의 메뉴 요청 결과와 실패·메뉴 없음 응답 구분
- 원본 응답 해시, 입력 객체와 파일의 불변성
- 원본 행·식별자 보존 및 사유 없는 항목 제외 방지
- 변형별 사진 참조와 가격이 없는 설명의 보존
- 고객용 결과의 가격 필드·가격 표현 비노출
- 결정성, 재투영의 멱등성, 검색 결과의 가게 간 분리
- 묶음·변형·제외 수의 정합성과 추가 검토 신호

보고서에는 모델 해시와 수집 시점을 함께 기록한다. 검토 목록의 카테고리 미분류, 용량 차이, 사진·설명 차이 등은 모두 오류를 의미하지 않는다. 보존 검사를 통과했다는 사실도 모든 묶음에 대한 사람의 의미 검토가 끝났다는 뜻은 아니다.
