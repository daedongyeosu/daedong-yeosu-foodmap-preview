# 상점과 도구를 한 화면에서 편집 — 2026-10-19

## 요청과 경계

- 문제: 휴대폰에서 상점과 도구가 긴 문서의 다른 위치에 있어 수정할 때마다 위아래를 왕복한다.
- 변경 대상: preview `store-studio` 편집 레이아웃과 도구 탐색, 관련 회귀검사만 수정한다.
- 보존: 기존 도구/입력 ID, 사진/가구/구성/상품 연결, 저장 형식, 되돌리기 이력, 고객 미리보기와 공개 화면의 기본 레이아웃.
- 변경 금지: 운영 메인, 관리자 서버, 실제 상품/주문 데이터, 결제, 배차, 젠딜리 연결과 운영 수집기.
- 기존 미커밋 `STORE_OWNER_EXPERIENCE_PLAN.md`는 수정/커밋하지 않는다.

## 설계

- 휴대폰은 위쪽 상점과 아래쪽 도구를 화면 안에서 분할한다. 경계 손잡이를 끌거나 키보드 방향키로 비율을 조절한다.
- PC는 상점 왼쪽, 도구 오른쪽이다. 도구가 길어도 도구 영역만 스크롤한다.
- 사진/가구 선택 시 기존 편집 컨트롤을 도구 영역 상단에서 보여준다. 이동은 문서 스크롤·상품 수정·저장·undo 기록을 만들지 않는다.
- 기존 선택 도구는 복제하지 않고 한 번 이동하며 모든 ID/이벤트와 잠금 로직을 유지한다. 일반 도구를 담은 `.tools`와 선택 도구는 서로 다른 영역으로 유지하여 일반 입력 활성화가 잠금된 사진/가구 컨트롤을 풀지 않도록 한다.
- 배치 정리/시안 파일도 같은 패널에서 접근한다. 전체 도구/상점 집중 모드를 왕복할 수 있다.
- 편집 모드에서만 높이 제한을 적용한다. 고객처럼 보기/공개 화면에서는 도구를 숨기고 기존 고객 스크롤/장바구니/확대를 유지한다.

## 검증

- 수정 전 `browser-shop-studio-workspace.mjs`: 사진 도구로 이동하면 상점이 화면 밖으로 나가 실패함을 재현했다.
- 완료 결과와 PR/배포 여부는 검사 뒤 추가한다. 물리 휴대전화 키보드·핀치 검증은 자동화의 화면 크기 변경과 구분한다.

### 로컬 검사 완료

- 활성 회귀검사 237개, 정적/데이터/공개 저장소 감사 및 관련 JS 문법 검사 통과. 검사 제외 목록과 기존 판정 기준은 유지한다.
- 원래 HTML의 278개 입력/기능 ID가 모두 정확히 한 번 남아 있음을 원격 main 원본과 대조했다. 메인 홈과 이전 미커밋 경험 계획 문서의 작업 전후 해시는 같다.
- 새 브라우저 검사는 390×844에서 사진 3장 등록, 선택 사진 이름 수정, 도구 끝까지 스크롤해도 상점 위치 유지, 가구 색 수정/undo/redo, 모든 도구 경로, 경계선 키보드 조절, 집중 모드 복귀, 새로고침 복원을 확인했다. 320×568·844×390·1280×900·1920×1080과 키보드 크기를 모의한 390×460도 확인했다.
- 기존 사장 작업/사진 목록 왕복/사진 교체/48종 가구/빵집 드래그·잠금·시안 파일 내려받기와 복원/4개 예시 장바구니 수량 검사를 통과했다. 작업 패널의 이동·접기·펼치기는 undo 이력을 추가하지 않는다.
- 구 검사에서 절대 화면 y<200을 요구하던 부분은 새 도구 패널 상단과 상점 동시 노출을 검사하도록 바꾸고, 집중 모드 복귀/파일 내보내기는 실제 새 탐색 경로로 수행한다. 캐시 키 검사만 새 자산 키로 갱신했다. 기능/잠금/복구 판정은 제거하지 않았다.
- 사진 업로드는 루프백 브라우저의 기기 저장뿐이며 새 검사 외부 요청·서버 쓰기는 0건이다. 공개 화면 도구 숨김과 고객 모드 복귀도 확인했다.
- 아직 실제 물리 휴대전화 키보드/핀치 및 실계정 서버 저장을 검사한 것은 아니다. preview 병합·배포는 사용자가 별도로 승인했으며 원격 검사 후 진행한다.
- 추가 역할 검사에서 집중 모드의 사진 선택이 도구를 다시 열어 포인터 제스처 중 상점 폭이 바뀌는 오류를 재현했다. 집중 모드에서는 자동 도구 열기를 하지 않고, 명시적으로 전체 도구로 복귀할 때 선택 도구를 보여준다. 같은 터치 검사에서 패널 숨김·상점 폭 보존을 재검증한다.
